# Джарвис для инвестиций — дизайн системы

Дата: 2026-08-07
Статус: согласован, готов к планированию реализации

## 1. Что это

Локальная система для владельца портфелей у четырёх российских брокеров (Т-Банк,
БКС, Сбер, Газпромбанк). Сводит все счета в единую картину, считает честную
доходность, показывает будущие денежные потоки, отвечает на вопросы о портфеле
и проактивно сообщает о событиях, которые касаются конкретных бумаг владельца.

Запускается на личной машине под Windows через Docker Compose. Единственный
пользователь — владелец портфеля. Аутентификации между пользователями нет и
не планируется.

### Цели

1. Видеть совокупный капитал и его структуру в одном месте, без переключения
   между четырьмя приложениями.
2. Знать реальную доходность с учётом пополнений, комиссий и налогов.
3. Знать, сколько денег придёт в ближайшие 12 месяцев и когда.
4. Обсуждать портфель с ИИ, который смотрит на настоящие цифры.
5. Получать редкие, но существенные сигналы о событиях у эмитентов портфеля.

### Явно не цели

- Торговля. Система никогда не выставляет заявки; токены брокеров запрашиваются
  только с правами на чтение.
- Мультипользовательский режим, публичный хостинг, мобильное приложение.
- Замена налоговой отчётности брокера. Налоговый модуль — инструмент
  планирования, что отражено в интерфейсе.

## 2. Ограничения реальности

Доступность данных у четырёх брокеров различается принципиально, и это
определяет архитектуру приёма данных.

| Источник | Доступ | Что отдаёт |
|---|---|---|
| Т-Банк | T-Invest API, персональный токен | позиции, операции, котировки |
| БКС | Trade API (HTTP + WebSocket), токен read-only | портфель, сделки, неторговые операции: дивиденды, купоны, комиссии |
| Сбер | публичного API нет | отчёт HTML/XLSX, выгружается вручную из веб-кабинета |
| Газпромбанк (Ньютон Инвестиции) | публичного API нет | отчёт из личного кабинета |
| MOEX ISS | открытый REST | котировки, справочник бумаг, купоны, дивиденды, оферты |
| ЦБ РФ | SOAP `DailyInfoWebServ` | ключевая ставка, курсы, RUONIA |

Следствие: синхронизация двухскоростная. Т-Банк и БКС обновляются по
расписанию сами, Сбер и ГПБ требуют, чтобы владелец выгрузил отчёт и перетащил
файл в интерфейс. Рекомендуемый формат для Сбера — HTML: он содержит больше
операций, чем XLSX.

Автоматический вход в кабинеты Сбера и ГПБ через headless-браузер рассмотрен
и отклонён: 2FA на каждый вход, хрупкость к любому редизайну, необходимость
хранить пароль от банка и вероятное нарушение условий обслуживания.

## 3. Ключевые решения

**Источник истины — журнал операций, а не снимок портфеля.** Хранится
неизменяемый журнал: покупки, продажи, дивиденды, купоны, комиссии, налоги,
пополнения, выводы, погашения, амортизации. Позиции, лоты и все метрики —
вычисляемые производные, которые можно пересобрать с нуля.

Причина: брокер отдаёт срез на текущий момент, а не историю. Из снимка нельзя
получить XIRR, налоговую базу, срок владения для ЛДВ и график стоимости за
прошлые периоды. Из журнала выводится всё перечисленное.

**Плюс ежедневные снимки стоимости.** Восстановить график стоимости портфеля
задним числом можно только имея цены всех бумаг на каждый день истории — это
дорого и неточно. Одна строка снимка в сутки делает график бесплатным.

**Синхронизация — это сверка, а не перезапись.** Позиции, посчитанные из
журнала, сравниваются со снимком брокера. Расхождение показывается владельцу
явно и никогда не устраняется автоматической правкой позиции: иначе ошибка
парсера тихо становится «истиной», а вся аналитика — мусором.

**Честная граница данных.** Реальная доходность считается с той даты, с которой
загружена история операций. За более ранний период показываются текущая
стоимость и структура, но не XIRR. Интерфейс сообщает эту границу явно.

**Разделение факта и предположения.** Фактические цифры (стоимость, доходность,
известные купоны) и предположения (сценарии Monte Carlo, консенсус-таргеты,
рассуждения ИИ) визуально различимы в интерфейсе. Смешение этих категорий —
главный способ обмануть себя красивым графиком.

## 4. Архитектура

Модульный монолит на FastAPI. Микросервисы для однопользовательской локальной
системы дали бы только накладные расходы.

```
Источники          Приём              Ядро            Производные      Потребители
─────────          ─────              ────            ───────────      ───────────
Т-Банк API    ─┐   connectors   ─┐                ┌─ positions/lots ─┐  REST API
БКС API       ─┤   reports      ─┤   ЖУРНАЛ       ├─ daily snapshot ─┤  Дашборд
Отчёт Сбера   ─┼──▶instruments  ─┼──▶ ОПЕРАЦИЙ ───┼─ analytics      ─┼─▶ИИ-чат
Отчёт ГПБ     ─┤   дедупликация ─┤   + сверка     ├─ forecast       ─┤  Планировщик
Ручной ввод   ─┤                 │                └─ tax            ─┘  Telegram
MOEX / ЦБ     ─┘                 │
```

### Модули бэкенда

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `connectors` | адаптеры брокеров за единым интерфейсом | внешние API |
| `reports` | парсеры HTML/XLSX Сбера и ГПБ | форматы файлов |
| `instruments` | справочник бумаг, сведение по ISIN, данные MOEX | MOEX ISS |
| `ledger` | журнал операций, дедупликация, идемпотентность | собственные таблицы |
| `positions` | свёртка журнала в позиции и лоты FIFO | ledger, instruments |
| `analytics` | XIRR, TWR, аллокация, look-through, бенчмарки | positions, prices |
| `forecast` | календарь выплат, YTM, сценарии Monte Carlo | instruments, positions |
| `tax` | НДФЛ, ЛДВ, сальдирование убытков | lots |
| `research` | существенные факты, отчётность, макро, предложения | instruments, positions |
| `alerts` | правила и события | всё выше, только чтение |
| `ai` | чат, реестр инструментов, провайдер LLM | публичные сервисы модулей |
| `scheduler` | задачи по расписанию | сервисы |
| `notify` | Telegram, лента событий | alerts, ai |
| `api` | REST-роутеры | сервисы |

Правило границ: `api`, `ai` и `notify` не обращаются к базе напрямую — только
через сервисные функции модулей. Это позволяет позже выставить MCP-сервер
поверх тех же функций без дублирования логики.

### Стек

- Бэкенд: Python 3.12+, FastAPI, SQLAlchemy, Alembic, APScheduler, `uv` как
  менеджер зависимостей.
- База: PostgreSQL 16.
- Фронтенд: React 19, TypeScript, Vite, TanStack Query, Zustand, Tailwind,
  shadcn/ui, Apache ECharts, `motion`.
- Запуск: Docker Compose — postgres, backend, frontend. Одна команда
  `docker compose up`.

## 5. Модель данных

Основные сущности PostgreSQL.

**`instrument`** — ISIN (ключ сведения между брокерами), тикер, SECID Мосбиржи,
тип (акция, облигация, фонд, фьючерс, валюта, металл), валюта, эмитент, сектор,
для фонда — класс актива для look-through, для облигации — дата погашения,
номинал, тип купона.

**`account`** — брокер, тип (брокерский или ИИС), номер, валюта, дата открытия.
Иерархия: портфель → брокер → счёт → позиция.

**`transaction`** — журнал. Счёт, инструмент, тип операции, дата и время,
количество, цена, сумма, валюта, комиссия, `external_id` брокера, источник
загрузки, хэш файла-источника, сырые данные операции как есть. Только вставка,
без обновлений и удалений.

Сырые данные хранятся не про запас: когда парсер Сбера ошибётся, журнал можно
будет пересобрать без повторной выгрузки отчётов из кабинета.

**`lot`** — партии для FIFO: инструмент, счёт, дата покупки, цена, исходное
количество, остаток. Нужны для налоговой базы и срока владения.

**`position`**, **`daily_snapshot`** — материализованные производные. Снимок
хранит дату, совокупную стоимость, разбивку по счетам и классам активов.

**`manual_asset`** — депозиты и прочие активы, вводимые руками: тело, ставка,
дата открытия и окончания, капитализация процентов, периодичность выплат.

**`price`**, **`fx_rate`** — история котировок и курсов ЦБ.

**`corporate_event`** — купоны, дивиденды, оферты, погашения, включая будущие.
Основа календаря выплат.

**`target_allocation`** — целевые доли по классам активов.

**`reconciliation`** — результат сверки: дата, счёт, инструмент, количество из
журнала, количество у брокера, статус, комментарий владельца.

**`news_item`**, **`filing`**, **`fundamental_metric`**, **`macro_event`** —
данные проактивного модуля (раздел 8).

**`proposal`**, **`proposal_outcome`** — предложения ИИ и их оценка задним
числом (раздел 8).

**`alert_rule`**, **`alert_event`**, **`chat_message`**, **`sync_run`** —
служебные сущности.

**Все денежные величины — `Decimal`, нигде не `float`.** Копеечные расхождения
в сверке порождают ложные срабатывания, которые быстро приучают игнорировать
предупреждения.

## 6. Приём данных и сверка

Единый конвейер, различается только первый шаг:

1. **Получить** — вызов API или разбор загруженного файла.
2. **Нормализовать** — привести к единому виду операции, найти инструмент по
   ISIN, завести новый, если не встречался.
3. **Отсеять дубли** — для API ключ дедупликации `external_id`; для отчётов
   натуральный ключ «счёт + инструмент + дата-время + количество + цена» плюс
   хэш файла. Повторная загрузка отчёта за пересекающийся период не создаёт ни
   одной лишней операции: периоды выгрузок у Сбера неизбежно нахлёстываются.
4. **Дописать в журнал**.
5. **Пересчитать производные** для затронутых счетов.
6. **Сверить** с состоянием у брокера.

### Сверка

Т-Банк и БКС отдают и операции, и текущие позиции. Позиции считаются из журнала
и сравниваются со снимком. Совпало — тихо. Не совпало — на дашборде плашка вида
«По ЛУКОЙЛ у Т-Банка 40 штук, в журнале 35 — вероятно, пропущена сделка от
12.03». Владелец решает: дозагрузить период, добавить корректирующую операцию
вручную или принять расхождение с комментарием.

Для Сбера и ГПБ сверка идёт против остатков на начало и конец периода из самого
отчёта.

При разборе отчётов отдельно отбрасываются строки «Итого» и раздел плановых
показателей — иначе операции на стыке периодов задваиваются.

### Расписание

| Задача | Частота |
|---|---|
| Синхронизация Т-Банка и БКС | дважды в день + кнопка «обновить сейчас» |
| Котировки MOEX | каждые 15 минут в торговые часы |
| Снимок портфеля | раз в сутки после закрытия торгов |
| Корпоративные события | еженедельно |
| Ключевая ставка и макро ЦБ | ежедневно |
| Существенные факты эмитентов | раз в час |

### Отказы

Каждый запуск синхронизации — запись со статусом. Отказ одного источника не
блокирует остальные: если БКС недоступен, данные Т-Банка обновляются, а на
карточке БКС появляется метка «данные от вчера, 14:30» вместо тихого показа
устаревших цифр как свежих.

Три отказа, которые точно произойдут, обрабатываются явно:

- **Протух refresh-токен БКС** (срок жизни 90 суток) — уведомление с
  инструкцией, где перевыпустить.
- **Изменился формат отчёта Сбера** — парсер валидирует структуру до разбора и
  отказывается целиком, а не загружает половину операций. Файл сохраняется для
  переразбора после починки парсера.
- **MOEX не отдал цену** — берётся последняя известная, данные помечаются как
  несвежие.

## 7. Расчётный слой

**Доходность считается двумя способами**, потому что это разные вопросы.
XIRR (денежно-взвешенная) — «сколько заработали мои деньги с учётом того, когда
я их вносил». TWR (взвешенная по времени) убирает эффект пополнений и отвечает
«хорошо ли выбраны бумаги»; только её корректно сравнивать с индексом.
Показываются обе, с пояснением, что есть что.

Разрезы: по счёту, брокеру, классу актива, отдельной бумаге; за день, месяц,
год, всё время.

**Аллокация с look-through.** Состав каждого БПИФ по отдельным бумагам публично
и стабильно не отдаётся, поэтому раскладка фонда до конкретных акций не
делается. Вместо этого у фонда есть классификация («фонд акций РФ», «фонд
облигаций», «денежный рынок»), и в аллокации по классам активов фонд
учитывается своим классом. Это устраняет главное искажение: без look-through
портфель с большой долей фондов на акции выглядит консервативным, не будучи им.

**Сведение эмитентов между брокерами.** Одна и та же бумага на четырёх счетах —
одна позиция в сводной картине. Реальная концентрация на эмитенте видна только
в объединённом портфеле.

**Календарь выплат** строится пересечением позиций с корпоративными событиями
MOEX: купоны с датами и суммами, погашения, оферты, объявленные дивиденды, плюс
проценты по депозитам. Отсюда же ожидаемый денежный поток на 12 месяцев и YTM
облигаций, посчитанный и к текущей цене, и к цене покупки владельца.

**Налоговый модуль** работает на лотах FIFO: НДФЛ по закрытым в текущем году
сделкам, бумаги с приближающимся трёхлетним сроком владения (с суммой экономии
при продаже после даты), убыточные позиции для сальдирования прибыли до конца
года. В интерфейсе помечено как оценка для планирования, а не замена справки
брокера.

**Бенчмарки**: индекс полной доходности Мосбиржи, вклад по ключевой ставке ЦБ,
инфляция. Отвечает на вопрос, был ли смысл в активном управлении.

**Сценарии**: Monte Carlo на исторической волатильности классов активов —
веер траекторий портфеля при заданном ежемесячном пополнении. Помечены как
предположение.

**Консенсус-таргеты аналитиков** — целевые цены по акциям портфеля. Публичного
источника с открытым API нет, поэтому данные собираются со страниц брокерских
аналитических обзоров, а при недоступности вводятся вручную. Это самая хрупкая
часть системы данных, поэтому она изолирована: отсутствие таргетов не ломает
ничего, кроме одного блока на экране аналитики. Отображаются с датой и
источником публикации и с разбросом оценок, а не одним усреднённым числом:
согласие аналитиков само по себе информативнее среднего.

**Фьючерсы** учитываются через операции вариационной маржи как обычные записи
журнала: позиция хранится в контрактах, финансовый результат накапливается
маржой, гарантийное обеспечение отражается как заблокированные средства на
счёте. Отдельного механизма переоценки не вводится — маржа уже является
переоценкой, приведённой брокером к деньгам.

**Валютные и замещающие облигации, иностранные бумаги** переоцениваются в рубли
по курсам ЦБ на дату операции и на дату оценки. Курсовая разница показывается
отдельной строкой в доходности: без этого непонятно, заработала бумага или
валюта.

**Целевые доли и ребалансировка**: заданная структура, текущее отклонение и
подсказка, куда направить следующее пополнение, чтобы выровняться без продаж и
налоговых последствий.

## 8. Проактивный аналитик

Модуль наблюдает за эмитентами портфеля и за макросредой, и изредка предлагает
действия. Новостные RSS-ленты сознательно исключены: официальные раскрытия дают
тот же сигнал без основного объёма шума.

### Источники

- **Существенные факты эмитентов** — e-disclosure.ru (Интерфакс). Публичного API
  нет, промышленный доступ платный, поэтому используется аккуратный скрейпинг с
  низкой частотой и только по эмитентам портфеля. Дублирующие источники —
  СКРИН и АЗИПИ, где ленты событий доступнее.
- **Отчётность** — МСФО и РСБУ с e-disclosure и страниц IR эмитентов.
- **Макро** — ЦБ РФ: ключевая ставка, даты заседаний, инфляция, курсы, RUONIA.

Наблюдение ведётся за эмитентами из портфеля и за отдельным списком интересов.

### Конвейер

1. **Сбор** по расписанию из раздела 6.
2. **Триаж дешёвой моделью**: каждое сообщение получает эмитента, тип
   (отчётность, дивиденды, регуляторика, санкции, менеджмент, макро) и оценку
   существенности от 0 до 3. Незначимое отсекается здесь.
3. **Глубокий анализ дорогой моделью** — только для существенного и всегда в
   контексте позиции владельца: не «эмитент опубликовал отчёт», а «доля 8%
   портфеля по средней цене 142 ₽, вот что изменилось и что это значит».
4. **Предложение**, если анализ приводит к выводу, что действие уместно.

### Конвейер отчётности

Календарь публикаций → скачивание документа → извлечение метрик (выручка,
EBITDA, чистая прибыль, чистый долг, свободный денежный поток, дивидендная
политика) → сравнение с предыдущими периодами → мультипликаторы, в том числе к
цене покупки владельца.

**Каждая извлечённая цифра хранится вместе с цитатой и номером страницы
источника.** LLM ошибается при чтении таблиц из PDF, и без проверки числа одним
кликом фундаментальный анализ превращается в правдоподобную выдумку.

### Предложения и их оценка

`proposal` — полноценная сущность: триггер, тезис, предлагаемое действие,
аргументы за и против, уверенность, срок актуальности, статус. Владелец
принимает, отклоняет или откладывает — с причиной.

**Система оценивает собственные советы задним числом.** Через 3, 6 и 12 месяцев
считается, что произошло бы при следовании предложению, и показывается
накопленная статистика. Без этого контура проактивный советчик остаётся
генератором убедительного текста, качество которого невозможно проверить.

### Ограничители

- Не более **трёх предложений в неделю**, приоритезация по влиянию (доля
  позиции × существенность события). Срочное — оферта, дефолт, отмена
  дивидендов — доставляется немедленно вне лимита.
- «Ничего не делать» — валидный и предпочтительный по умолчанию исход. Модель
  обязана обосновывать действие, а не бездействие.
- **Геополитика ограничена фиксацией свершившихся фактов** (принят закон,
  изменён НДПИ для отрасли, введены ограничения) и их влиянием на конкретные
  бумаги. Прогнозы политических событий не формулируются: это область, где
  модель слабее всего, а уверенный тон особенно обманчив.

## 9. ИИ-слой

**Модель не получает портфель в промпте — она запрашивает данные
инструментами.** Реестр инструментов: обзор портфеля, позиции, история
операций, метрики доходности, аллокация, календарь выплат, налоговая ситуация,
предложение по ребалансировке, сравнение с бенчмарком, запуск сценария, поиск
инструмента, последние существенные факты по бумаге, метрики отчётности.

Причина: числа в ответе всегда происходят из реального расчёта, а не из памяти
модели. Дополнительно действует системное правило — не называть чисел, которых
не вернул инструмент. Галлюцинацию про доходность владелец может не заметить, а
решение принять.

Чат знает, **что сейчас на экране** — какой раздел, фильтр и период открыты.
Вопрос «а почему тут просадка?» работает без уточнений.

Реестр инструментов вынесен из обработчика чата в отдельный модуль. Тот же
реестр в шестой фазе выставляется как MCP-сервер, и внешние клиенты
(Claude Desktop, ChatGPT) получают те же возможности без дублирования кода.

Провайдер модели — за абстракцией, реализация одна: облачный API (Claude или
GPT, выбирается в настройках). Локальная модель через Ollama возможна позже
той же абстракцией.

**Периодические сводки** формирует планировщик: будит модель с тем же набором
инструментов и промптом «что изменилось, что требует внимания, что произойдёт в
ближайший месяц», результат уходит в Telegram и в ленту событий.

Периодические задачи ChatGPT требуют публичного HTTPS-адреса до машины
(туннель), что означает вынос портфеля наружу и постоянно открытую дверь
снаружи. Основной путь — внутренний планировщик, результат для владельца
идентичен. Внешний MCP-коннектор остаётся опциональной надстройкой шестой фазы.

**Голос**: распознавание локальным Whisper, чтобы вопросы о деньгах не уходили
в облако лишний раз. Ответ текстом, озвучка опциональна.

## 10. Фронтенд

Главный экран — **командный центр**: сводка капитала и график стоимости сверху,
ниже сетка виджетов (аллокация, разбивка по брокерам, календарь выплат, топ
движений). Чат — выдвижная панель справа по кнопке.

Экраны: Портфель, Активы, Сделки и импорт, Календарь выплат, Аналитика, Налоги,
События и предложения, Настройки.

**Визуальный стиль** — тёмно-синий градиент, мягкие тени, крупная цифра
капитала, строки на подложках со скруглением. Современный продуктовый вид.

Обязательные детали: **табличные цифры** (`tabular-nums`) во всех числовых
колонках, иначе суммы дёргаются при обновлении котировок; знак изменения
передаётся стрелкой и цветом одновременно, а не только цветом.

**Анимации** встроены в дизайн-систему с регулятором в настройках:
выключены / сдержанные / выразительные, по умолчанию сдержанные, с учётом
системного `prefers-reduced-motion`.

Где анимация помогает: перетекание чисел к новому значению (видно направление
изменения), морфинг линии графика при смене периода, пружинный выезд панели
чата и раскрытие строк таблицы, переползание сегментов аллокации при смене
фильтра.

Где не применяется: мигание строк при каждом тике котировки и любые задержки на
пути к цифре, за которой владелец пришёл.

## 11. Безопасность и приватность

- Токены брокеров — в `.env` рядом с проектом, не в базе и не в git. При
  локальном запуске это адекватно: тот, кто добрался до файлов машины, добрался
  до всего.
- Токены запрашиваются **только на чтение**. Торговые права системе не выдаются
  вообще, чтобы ни ошибка в коде, ни галлюцинация модели не могли выставить
  заявку.
- Наружу система не публикуется. Единственный сценарий с внешним доступом —
  опциональный MCP-туннель шестой фазы, который включается явно.
- В облачный LLM уходят данные портфеля в объёме ответов инструментов. Это
  осознанный размен на качество рассуждений; локальная модель остаётся
  доступной альтернативой через ту же абстракцию провайдера.

## 12. Тестирование

Покрытие верстки не преследуется. Критичны три области, где ошибка не падает, а
тихо показывает неверную цифру.

**Финансовая математика** — эталонные тесты: XIRR против заранее посчитанных
значений, FIFO-списание против разобранного вручную примера, НКД и амортизация
облигаций на реальных выпусках, конвертация валют по курсам ЦБ.

**Парсеры отчётов** — golden-файлы: обезличенный реальный отчёт на входе,
ожидаемый список операций на выходе. Каждый новый формат добавляет фикстуру.
Отдельные случаи: строки «Итого», плановые показатели, операции на стыке
периодов, повторная загрузка пересекающегося периода.

**Сверка** — свойство «журнал, свёрнутый в позиции, сходится со снимком
брокера» проверяется на сгенерированных наборах операций, включая сплиты,
частичные продажи, погашения и амортизацию.

Коннекторы тестируются на записанных ответах API, без обращения к сети. Для
фронтенда — Vitest на логику расчёта и форматирования, два-три сценария
Playwright на ключевые пути. Качество ответов ИИ автоматически не проверяется;
проверяется, что инструменты вызываются и возвращают валидные данные.

## 13. Фазы поставки

Каждая фаза заканчивается работающей системой. Порядок выбран так, чтобы самая
рискованная часть — журнал и сверка — проверилась на настоящих данных как можно
раньше.

**Фаза 1. Ядро и Т-Банк.** Docker Compose, база, миграции, журнал операций,
коннектор T-Invest API, цены MOEX, свёртка в позиции и лоты, ежедневные снимки
стоимости, сверка, дашборд со сводкой капитала, графиком стоимости и
аллокацией. Результат: владелец видит свой настоящий портфель Т-Банка.

Снимки входят в первую фазу, а не во вторую: график стоимости заявлен здесь же,
а строить его не из чего, пока снимки не начали накапливаться.

**Фаза 2. Остальные источники.** Коннектор БКС Trade API, парсеры отчётов Сбера
и ГПБ, загрузка файлов в интерфейсе, ручные активы и депозиты, ИИС и несколько
счетов у брокера. Результат: полная картина капитала.

**Фаза 3. Аналитика.** XIRR и TWR, look-through по фондам, сведение эмитентов,
календарь выплат и YTM, бенчмарки, целевые доли и ребалансировка, налоговый
модуль.

**Фаза 4. ИИ-чат.** Реестр инструментов, панель чата, контекст экрана,
стриминг ответов, история диалогов.

**Фаза 5. Проактивный аналитик.** Существенные факты, конвейер отчётности,
макро ЦБ, предложения, контур оценки качества советов, сценарии Monte Carlo,
консенсус-таргеты аналитиков.

**Фаза 6. Автоматизация.** Планировщик сводок, Telegram-бот, алерты, голосовой
ввод через Whisper, MCP-сервер наружу.

Спецификация описывает систему целиком; план реализации пишется на одну фазу.
Первый план — Фаза 1.

## 14. Что осознанно не делаем

- **Автологин в кабинеты Сбера и ГПБ** — 2FA, хрупкость, хранение банковского
  пароля, риск нарушения условий обслуживания.
- **Look-through фондов до отдельных бумаг** — состав БПИФ не отдаётся публично
  и стабильно; классификации по классу актива достаточно для честной аллокации.
- **Новостные RSS-ленты** — шум превышает сигнал, официальные раскрытия
  покрывают существенное.
- **Прогнозы политических событий** — область наименьшей надёжности модели.
- **Микросервисы, очереди сообщений, Kubernetes** — накладные расходы без
  выгоды для однопользовательской локальной системы.
- **Торговые операции** — система принципиально только читает.

## 15. Известные риски

**Формат отчётов Сбера и ГПБ изменится.** Смягчение: валидация структуры до
разбора, отказ целиком вместо частичной загрузки, сохранение исходных файлов
для переразбора, golden-тесты на каждый известный формат.

**Скрейпинг e-disclosure может быть ограничен по частоте или заблокирован.**
Смягчение: низкая частота, только эмитенты портфеля, дублирующие источники
(СКРИН, АЗИПИ), деградация до ручного просмотра без поломки остальной системы.

**Извлечение метрик из PDF-отчётности будет ошибаться.** Смягчение: цитата и
номер страницы у каждого числа, отображение уверенности, возможность исправить
значение вручную.

**Проактивный модуль спровоцирует переторговку.** Смягчение: лимит трёх
предложений в неделю, обязательное обоснование действия, контур оценки качества
советов задним числом.

**Расходы на LLM вырастут незаметно.** Смягчение: дешёвая модель на триаже,
дорогая только на существенном, счётчик расходов в настройках.

## 16. Что понадобится установить

Перед первой фазой: Docker Desktop, Python 3.12+ с `uv`, Node.js 20+ с `pnpm`.

Внешние доступы: токен T-Invest API, токен БКС Trade API с правами только на
чтение, ключ API выбранной модели. Telegram-бот и Whisper — к шестой фазе.
